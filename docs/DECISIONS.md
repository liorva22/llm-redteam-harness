# Design decisions

| # | Decision | Alternatives | Why |
|---|----------|--------------|-----|
| 1 | **Deterministic success oracle**: canary token, 8-word system-prompt shingles, digit-normalized known PII, and a unique marker phrase per attack | LLM judge decides whether an attack "worked" | No judge variance and no judge cost. A leak either happened or it didn't, so nightly numbers are comparable night to night. Each jailbreak attack plants a unique marker, which makes "did the model switch persona?" checkable. |
| 2 | **Worst-case mock target** (complies with every attack that reaches it) | A scripted model that is vulnerable to some attacks | A scripted vulnerability profile would make the reported ASR whatever I scripted. A worst case makes the mock-mode ASR a clean, honest quantity: the share of attacks the guardrails fail to stop. Real model robustness is only measured in live mode. |
| 3 | **Four layers, each switchable** (`none` → `rules` → `rules+classifier` → `full`), with every config replayed | Report only the full stack | The ablation shows what each layer buys. In mock mode, rules alone leave 48.6% ASR, the classifier brings it to 10.0%, and the output filter to 4.3%. |
| 4 | **Classifier = Claude Haiku when live, local TF-IDF + LR in mock**, trained on a separate 60-example set (a test asserts no overlap with the suite) | Train on part of the suite; no classifier in mock mode | Training on the suite would leak test data. Skipping the classifier in mock would hide the most interesting layer. It's reported by name (`local-tfidf-lr`), never as "the LLM classifier". |
| 5 | **Output filter matches *known* secrets** (canary, prompt shingles, the directory's PII digits) in addition to generic PII regexes | Generic regex DLP only | The app knows exactly what it must not leak. Digit normalization catches "5 5 5 0 1 4 2"-style obfuscation, which a regex misses. |
| 6 | **Generic output redaction skips emails** | Redact all emails | The assistant's own help-desk address (`hr@acme.example`) was being redacted from benign answers. Employee emails are caught by the known-secret match. |
| 7 | **Suite as versioned JSON in the repo** (`suites/v1.json`, semver) | Database table; YAML | Diffable in PRs, and each replay row records the suite version, so a changed number can always be traced to code or suite changes. |
| 8 | **Nightly = scheduled GitHub Action**, live when an `ANTHROPIC_API_KEY` secret exists and mock otherwise. Fails on ASR > 10% or FPR > 10% | External scheduler | Zero infrastructure, results are uploaded as artifacts, and a regression turns the nightly red. |
| 9 | **Attacks are generic and educational**, aimed only at this project's toy app | Real-world jailbreak corpora | Per the project brief: nothing here targets third-party products, and the "payloads" are harmless marker phrases. |
| 10 | **Fixed the rule bug instead of tuning on the suite.** `ai_addressed_directive` ended in `\b` after `:`, so it could never match. | Tweak rules until the suite passes | The fix restored the rule's intended behavior (regression test added). The rules were not otherwise adjusted after seeing results. The three indirect-injection misses are reported as-is. |
